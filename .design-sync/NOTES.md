# design-sync notes — Crowi Design System

Repo-specific gotchas for `/design-sync`. Append whenever something new is learned.

## Shape & entry
- Shape = `package` (synth-entry). `@crowi/web` is a **private Next.js app**, not a library — it has no `dist`/`exports` entry. We hand-write `packages/web/.ds-entry.mjs` (regenerated by `.design-sync/prepare.mjs`) that `export *`s ONLY the pure shadcn primitives. `PKG_DIR` resolves to `packages/web` because the entry lives there (build.mjs walks up from `--entry` to the nearest named `package.json`).
- **Excluded on purpose**: the 5 i18n glue components under `ui/` — `access-denied-card`, `error-alert`, `not-found-card`, `loading-spinner`, `pager` — import `@paraglide/*` and would drag i18n (with no locale context) into the standalone bundle. Also excluded: `sonner` (a `<Toaster>` portal mount with no static render) and `form-error-list`.
- 17 synced components (all `src/components/ui/*.tsx`): Alert, AlertDialog, Avatar, Button, Card, Dialog, DropdownMenu, Input, Label, Popover, Select, Sheet, Slider, Switch, Tabs, Textarea, Tooltip.

## Build commands
- Deps live in `.ds-sync/node_modules` (esbuild, ts-morph, @types/react, @tailwindcss/cli, playwright). Install with `(cd .ds-sync && npm i …)` — never at repo root.
- CSS is **Tailwind v4 CSS-first** (no `tailwind.config.*`). Compile: from `packages/web`, `../../.ds-sync/node_modules/.bin/tailwindcss -i src/app/globals.css -o .ds-compiled.css`. `cfg.cssEntry = .ds-compiled.css` (bounded to PKG_DIR). It becomes `_ds_bundle.css` = utilities + `:root`/`.dark` token values.
- Build: `node .ds-sync/package-build.mjs --config .design-sync/config.json --node-modules packages/web/node_modules --entry packages/web/.ds-entry.mjs --out ./ds-bundle`

## Render check / capture — system Chrome, no 200MB download
- `playwright` JS installed with `PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1`; both validate and capture honor `DS_CHROMIUM_PATH`. Set `DS_CHROMIUM_PATH="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome"` for `package-validate.mjs` and `package-capture.mjs`. This also drives the user's real Chrome (their stated preference).

## `.d.ts` — dtsPropsFor is mandatory
- crowi's shadcn primitives use inline anonymous prop signatures (no named `<Name>Props`), so ts-morph extraction returns the empty `[key: string]: unknown` stub for every component. Each component needs a hand-written `cfg.dtsPropsFor.<Name>` interface body (the design agent codes against these).

## Preview authoring conventions
- `.design-sync/previews/<Name>.tsx`, markerless. Import from `'@crowi/web'` (shimmed to `window.CrowiUI`); every sub-export (CardHeader, SelectItem, …) is available from the same import. Each named export = one graded cell. JSX automatic (no React import needed except for types).
- **Use inline styles for wrapper layout** (`display:flex`, `gap`, `width`). Arbitrary Tailwind values invented in a preview (e.g. `w-[360px]`) may not exist in the compiled CSS; the component's OWN classes are always compiled. Widely-used utilities are present but inline styles are the safe default for wrappers.
- **Overlays render open statically** via `defaultOpen`/`open`. For portaled content (Select/Popover/DropdownMenu/Tooltip) pass `position="popper"` — verified to render correctly in headless Chrome (see Select `Open` cell).
- Realistic, crowi-flavored content (visibility Public/Restricted/Private, pages/spaces/wiki), never `foo`/`test`.

## Known render warns (triaged — non-blocking; FINAL state = 2 warns)
Final validate: **17/17 previews render cleanly, 0 bad**, exactly 2 warns:
- `[FONT_MISSING]` / `[TOKENS_MISSING]`: `--font-geist-sans`, `--font-noto-sans-jp`, `--font-geist-mono` are injected by Next's font loader at runtime → absent in a standalone bundle; text falls back to system sans. `Hiragino Kaku Gothic Pro` is a system JP fallback. `--shiki-light`/`--shiki-dark` (markdown code highlighting) and `--crowi-primary` are not referenced by the 17 primitives. All accepted for this sync — components render correctly, only the brand font differs.

## Grid-view overrides (cfg.overrides)
`[GRID_OVERFLOW]` fired for how cards present in the product's grid (per-story captures were fine). Applied: `cardMode:'column'` for wide cards (Alert, Card, Tabs); `cardMode:'single'` + `primaryStory` for portaled overlays (AlertDialog/Dialog/DropdownMenu/Popover/Select/Sheet/Tooltip). These are presentation-only — grades carry forward; column/single can't re-flag `wide`.

## typescript parse-check quirk
`package-validate.mjs`'s optional `.d.ts` parse check prints `(.d.ts parse check skipped — typescript not in node_modules)` because the `typescript` npm build installed into `.ds-sync` has a nonstandard layout (no `lib/typescript.js`), so its `import('typescript')` throws. Non-blocking: the emitted `.d.ts` were parse-verified separately via ts-morph (0 syntax errors). If you want the built-in check to run, install a standard `typescript` build into `.ds-sync`.

## Re-sync risks
- `packages/web/.ds-entry.mjs` and `.ds-compiled.css` are gitignored build inputs, regenerated by `.design-sync/prepare.mjs` (set as `cfg.buildCmd`). A fresh clone must run prepare before the converter.
- The Tailwind compile scans all of `packages/web/src`, so the CSS covers more than the 17 components (harmless superset). If new arbitrary values are needed in previews, re-run the compile after adding them to a scanned file, or use inline styles.
- Fonts are deliberately NOT shipped (runtime-injected). If brand-font fidelity is later wanted, wire Geist + Noto Sans JP via `cfg.extraFonts`.
