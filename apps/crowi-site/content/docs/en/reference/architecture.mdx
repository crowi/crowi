This page gives a bird's-eye view of the entire Crowi 2.0 (codename
*Reignite*) codebase structure. Crowi has been rebuilt from a legacy
Express + Swig + jQuery monolith into a Hono API plus a Next.js 16
frontend (RFC-0006, landed 2026-05-22).

## Monorepo layout

The repository is a Turborepo + pnpm workspaces monorepo.

```
crowi/
├── apps/
│   ├── crowi-runner/        # reference runner project — full image source (@crowi/runner-app)
│   ├── crowi-runner-slim/   # minimal runner project — slim image source (@crowi/runner-app-slim)
│   └── crowi-site/          # crowi.wiki LP + docs (Next.js + Fumadocs, :4303)
└── packages/
    ├── api/                 # Hono 4 API (:4301) — plugin-free (SDK + core only)
    ├── api-contract/        # Hono (@hono/zod-openapi) contracts + Zod schemas
    ├── web/                 # Next.js 16 App Router frontend (:4302)
    ├── collab/              # Real-time collaboration (Hocuspocus) library
    ├── runner/              # @crowi/runner: config loader + plugin resolver (createRequire)
    ├── plugin-api/          # Plugin SDK (CrowiPlugin / registries / context)
    ├── plugin-aws/          # Shared AWS credentials base for AWS plugins
    ├── plugin-storage-{local,aws-s3}/
    ├── plugin-search-{mongo,elasticsearch,opensearch}/
    ├── plugin-mail-{smtp,aws-ses,resend}/
    ├── plugin-renderer-{katex,plantuml,mermaid,crowi-legacy}/
    ├── plugin-google/        # Google (OIDC) auth provider
    ├── plugin-slack/         # Slack integration (page-link unfurling)
    ├── svg-sanitize/         # SVG sanitizer used by the plugin SDK (internal)
    ├── cli/                  # `crowi` end-user CLI (@crowi/cli)
    ├── admin-cli/            # `crowi-admin` CLI
    ├── e2e/                  # Playwright E2E suite
    └── tsconfig/             # Shared tsconfig presets
```

Three big building blocks — the **API** (`packages/api`), the **Web**
frontend (`packages/web`), and the **API contracts**
(`packages/api-contract`) — sit at the center, with the plugins and the
runner projects (`apps/crowi-runner*`) around them.

The api is **plugin-free**: `@crowi/api` ships only the SDK
(`@crowi/plugin-api`) and core, bundling no drivers. The plugins are
owned by a **runner project** — a small npm project that depends on
`@crowi/api` plus the chosen `@crowi/plugin-*` packages, and carries a
`crowi.config.json` (which plugins to load + which driver each registry
uses) and an `.env`. At boot the `@crowi/runner` library resolves the
listed plugins from the runner project's `node_modules/` via
`createRequire(projectDir)`, so adding or removing a plugin needs no api
rebuild. `apps/crowi-runner` is the reference runner project (its
`crowi.config.json` is `apps/crowi-runner/crowi.config.json`); a
self-hosting operator writes their own.

## Tech stack

| Layer | Technology |
| ----- | ---------- |
| API | Hono 4 + Mongoose + JWT auth |
| Web | Next.js 16 (App Router, Turbopack) + React 19 + Tailwind CSS v4 + shadcn/ui + @tanstack/react-query |
| Site | Next.js 16 (static export) + Fumadocs UI + i18n (ja / en) |
| Shared | TypeScript 5.x strict, pnpm workspaces, Turborepo |
| Lint / Format | Biome (format) + ESLint (lint), lefthook hooks |
| Tests | Jest + supertest (API). CI uses a `services.mongo` container; `mongodb-memory-server` is a local-dev fallback only |

## API server (`packages/api`)

### Boot sequence

`Crowi.init()` initialises subsystems roughly in the following order:

1. `setupEncryption` — prepares the encryption key provider for sensitive Config
2. `setupDatabase` — connects to MongoDB
3. `setupModels` — registers Mongoose models
4. `setupRedisClient` — connects the Redis client
5. `setupSessionConfig` — session configuration
6. `setupConfig` — loads the Config collection
7. `migrateConfig` — config migration
8. `runAwsConfigMigration` — migrates v1 AWS config (before plugins)
9. `setupRenderer` — registers the core renderer pipeline (TOC / wikilink / mention / code block / emoji shortcodes / link cards)
10. `setupPlugins` — starts plugins resolved by `@crowi/runner`
11. `setupMailer` / `setupSlack` — mail / Slack
12. `setupDNSCache` / `setupLRU`
13. `buildServer` — builds the Hono server

The renderer boots **before** plugins. This means the registry handed
to plugins already has the core registrations in place, and renderer
plugins append on top of it.

Emoji shortcodes and link cards (`@[card](url)`) are bundled into this
core pipeline rather than shipped as renderer plugins — they work with
no install step and no `crowi.config.json` entry. KaTeX / PlantUML /
Mermaid / crowi-legacy stay optional renderer plugins, resolved the same
way as any other `@crowi/plugin-*` package. See
[Renderer plugins](../plugins/renderers) for the full core-vs-optional
boundary.

### Routing

The API has three route families:

- Public Hono routes (no auth)
- Authenticated Hono routes (under `jwtAuth(crowi)`; most page / user / comment endpoints)
- Admin Hono routes (under `jwtAdminRequired(crowi)` = JWT + `user.admin === true`)

Endpoint handlers live under `hono/handlers/` (admin handlers under
`hono/handlers/admin/`); the Hono app is assembled in `hono/app.ts`
and middleware lives in `hono/middleware/`.

### Auth and models

Authentication uses JWT (access token + refresh token). Mongoose models
include Page (with grant) / Revision / User / Comment / Bookmark / Like
/ Watcher / Notification / Activity / Config / Backlink / Share /
Attachment, among others.

Sensitive config (OAuth secrets, AWS keys, SMTP password, Slack token)
is encrypted with AES-256-GCM. See [Config encryption](../operations/encryption)
for details.

### Real-time collaboration

Hocuspocus is not a separate process — it is attached inside the api
process as the `@crowi/collab` library. It uses the api's `http.Server`
in `ws noServer` mode to handle `/collab/*` upgrades (collab) and
`/presence/*` upgrades (RFC-0005 page presence). See
[Operating real-time collaboration](../operations/realtime-collab) for
details.

### Official Docker images

Both official images are built from `packages/api/Dockerfile`, each from
a runner project rather than from `@crowi/api` directly:

- **full** (from `apps/crowi-runner`) — bundles all twelve first-party
  drivers. Switch storage / search / mail driver by editing
  `crowi.config.json`; no rebuild.
- **slim** (from `apps/crowi-runner-slim`) — only the three
  implicit-default drivers (`storage-local` + `search-mongo` +
  `mail-smtp`), so it runs against MongoDB alone. A minimal base for
  operators who want to assemble their own plugin set.

The api requires a Node runtime (it cannot run on Workers; Containers
are fine).

## Web frontend (`packages/web`)

The web app is a **separate deployable** with zero plugin dependencies:
it talks to the api over HTTP and knows nothing about which drivers the
runner project loaded. It uses the Next.js 16 App Router, dividing
`src/app/` into three Route Groups.

| Route Group | Contents | Gate |
| ----------- | -------- | ---- |
| `(public)/` | login / register / installer | none |
| `(auth)/` | regular page features | redirect via `useAuth` |
| `(admin)/` | admin screens | `user.admin === true` |

Data fetching uses `@tanstack/react-query` throughout. `apiClientV2`
(the typed Hono RPC client returned by `createClient`, typed as
`CrowiApiClient`) is generated from the shared contracts, and hooks
live in `src/lib/use-*.ts`. Shared UI consists of
`components/ui/` (shadcn) plus cross-cutting primitives like
`LoadingSpinner` / `ErrorAlert` / `AccessDeniedCard` / `NotFoundCard`.

## API contracts (`packages/api-contract`)

All API contracts and Zod schemas are consolidated here, built by tsup
into CJS + ESM + `.d.ts`. Contracts are `@hono/zod-openapi`
`createRoute(...)` route definitions, mounted under `/api`, grouped
by top-level namespace (`page`, `user`, `bookmark`, `notification`,
`admin`, `adminCrypto`, …). The Scalar API Reference is exposed at
`/api/docs`.

Defining contracts in one place keeps the API implementation and the
Web client calls aligned against the same types. After editing
contracts, regenerate the dts with
`pnpm --filter @crowi/api-contract build`.

## Migration history

The migration to Crowi 2.0 proceeded feature by feature. Legacy Express
controllers + Swig views were re-implemented as Hono handlers + Next.js
pages, and the legacy Express mount (`/_api/*`, `/login`, etc.) was
fully retired as part of the RFC-0006 cutover on 2026-05-22. The
current phase status is reflected in the [release notes](https://github.com/crowi/crowi/releases).
