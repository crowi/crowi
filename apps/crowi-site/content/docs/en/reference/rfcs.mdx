Major design decisions for Crowi 2.0 are documented as **RFCs (Request
for Comments)** under `docs/rfcs/` in the repository. This page lists
and summarises the RFCs that currently exist.

> **Note**: Crowi v2 is under active alpha development. RFC content may
> still be revised as implementation progresses — the "round" label on
> each RFC indicates how many revisions that document has been through —
> but most of the proposals below have already shipped in the codebase.
> The Status column reflects the implementation state, not the document
> state.

## RFC-0001: Plugin Architecture

A proposal to pull four mutually independent concerns — file storage,
external search, auth providers, and notification sinks — out of the
core and turn them into independently distributable plugins. The core
keeps "batteries-included" defaults that work without a single plugin
installed. Operators add plugins via a CLI and configure them from the
admin UI. This is the foundation of the Crowi 2.0 plugin model.

→ For a user-facing explanation, see [Plugin architecture](../plugins/overview).

## RFC-0002: Renderer Plugin Architecture

A proposal to add a fifth concern — "rendering" — to the RFC-0001 plugin
model. Markdown parsing, AST transformation, embed handling, and HTML
rendering become plugin extension points. Three design commitments
characterise it: SSR-first, no external API calls while editing, and no
new syntax (mostly). Phase 1–6 are implemented, with Phase 7 onward in
progress.

→ For a user-facing explanation, see [Renderer plugins](../plugins/renderers).

## RFC-0003: Real-time Collaborative Editing

A proposal to add real-time collaborative editing to Crowi 2.1. It uses
Yjs as the synchronisation engine and Hocuspocus as the WebSocket
backend. Multiple users can edit the same page simultaneously, and
changes converge deterministically via CRDT semantics. The canonical
Markdown source is written out to a `Revision` document on explicit
save.

→ For a user-facing explanation, see [Real-time editing](../guide/realtime-editing);
for operators, see [Operating real-time collaboration](../operations/realtime-collab).

## RFC-0004: Editor UX Enhancement

A proposal to add four editor productivity features on top of the
minimal CodeMirror 6 editor from RFC-0003: autocomplete for `@user`
mentions and `[[Page` wikilinks, paste handling for URLs / images,
drag-and-drop upload, and a management view for draft pages
(`/me/creating-pages`). Landed for Crowi 2.2.

## RFC-0005: Page Presence & Header UI

A proposal for two related changes to the page view. One is a **live
presence row** above the title — it shows, in real time, who is
currently viewing the page, with editing users distinguished by a
badge. The other is a **meta chip row restructure** — likes, views,
comments, and backlinks become a uniform set of clickable chips,
separating the "who's here now" signal from "who has visited". The
presence WebSocket attaches to the same api process as RFC-0003's
`/collab`, so it adds no dedicated infrastructure.

→ For a user-facing explanation, see [Working with pages](../guide/pages).

## RFC-0006: HTTP API — Express + ts-rest → Hono

A proposal to replace the Express + ts-rest stack with Hono +
`@hono/zod-openapi` as the framework backing the `/api/v2/*` HTTP
layer. Zod schemas under `packages/api-contract/src/schemas/` move
over essentially unchanged; ts-rest contracts are rewritten as
`createRoute` route definitions; the api app exposes a Scalar API
Reference at `/api/v2/docs`. The legacy `/api/*` Express mount is
also retired as part of the cutover. Landed on 2026-05-22.

→ For the resulting architecture, see [Architecture](./architecture).

## How to read the RFCs

The RFC documents live under `docs/rfcs/` in the repository, and the
links in the table above open them directly on GitHub. Each RFC opens
with a metadata block stating the status, target release, and dependent
RFCs, followed by Summary / Goals / Non-goals / detailed design.
