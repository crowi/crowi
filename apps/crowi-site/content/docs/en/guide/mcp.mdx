Crowi ships with an **MCP (Model Context Protocol) server** built in. Any MCP-capable AI client — Claude Desktop, Claude Code, Codex CLI and others — can search, read, create and update wiki pages through it. There is nothing extra to install.

The endpoint is `/api/mcp` on the same address you open the wiki with, for example `https://wiki.example.com/api/mcp`.

## 1. Create a token

MCP authenticates with a **personal access token**. Issue one following [Account and security](./account-security).

There are two scopes to choose from. `pages:read` allows search, reading, history, backlinks and page listings; `pages:write` allows creating, updating, renaming, deleting and restoring (the full catalog is on [HTTP API](../reference/api)).

<Callout type="info">
  **Start read-only (`pages:read` alone).** A token acts as you and can never reach a page you cannot see, but a write scope leaves room for the AI to follow instructions embedded in a page it read and go on to delete or rename something. When you do need writes, issue a separate short-lived token for that job.
</Callout>

Admin scopes cannot be attached to a token, so nothing in the admin panel is reachable over MCP.

## 2. Connect a client

The same settings screen shows ready-made connection commands for Claude Code and Codex CLI. Written out by hand it looks like this:

```sh
claude mcp add --transport http crowi https://wiki.example.com/api/mcp \
  --header "Authorization: Bearer crowi_pat_<your token>"
```

Once connected, the client sees the `crowi_*` tools and the AI can call them on your behalf.

## Available tools

The tools, and the scope each one needs, are listed on [HTTP API](../reference/api). The reading tools work under `pages:read` and the writing tools under `pages:write`.

`crowi_update_page` takes the revision the client read along with the update. If someone else saved the page in the meantime the call fails as a conflict, and the AI re-reads the page and tries again.

### Writing an artifact page

`crowi_create_page` / `crowi_update_page` accept an optional `content_type` field, `'markdown'` or `'artifact'`. Omit it and the server falls back to its own default: `crowi_create_page` makes a markdown page, `crowi_update_page` keeps the page's current kind — an update call that omits `content_type` never turns an artifact page back into markdown. Set it to `'artifact'` and `body` must be a single self-contained HTML document: no external `<script>` / `<link>` / `<img>` / module references, and no relative resource paths — embed any binary asset as a `data:` URI. Links to other wiki pages are the one exception: an HTML `a` / `area` `href` may be a page path relative to the artifact's own page (`/team/guide`, `./guide`, `../guide#section`, `guide`). A literal `%` in a page name is written `%25` in the `href` (`100%25done` resolves to the page `100%done`; `100%done` is rejected). See the [CLI artifact guide](./cli#linking-from-an-artifact-to-a-wiki-page) for the details of how links are written and behave. The kind is never inferred from the body's content, so declare it explicitly whenever you mean an artifact.

Reading a page back (`crowi_get_page` / `crowi_get_revision`) reports its kind as `content_type` in the result, so the AI can tell whether the returned body is markdown or HTML before it treats it as either.

External stylesheets are not allowed except Google Fonts stylesheets when the wiki administrator has enabled web fonts; otherwise, Google Fonts references are rejected with FONT_REFERENCE_FORBIDDEN.

An `href` may hold a same-document `#id` or a wiki page path, optionally with a page fragment (`/guide#overview`). A page path cannot carry a query (`?`), and an absolute link to a reserved route such as `/admin`, `/logout`, the API or delivery paths is rejected when the page is saved. A relative link is judged by the parent after it resolves it from the page's own position, when the link is clicked. The page-ID forms (`<wiki origin>/<page id>` and `/<page id>`) cannot be used inside an artifact either. Fix a broken same-document link such as `#` or `#a?b` to a `#id`.

External URLs (`https:`, `mailto:`, `tel:`, and protocol-relative `//host/...`) cannot be links: remove the `href` and keep the address as body text. Rewrite a full or protocol-relative URL for this wiki as a page path such as `/team/guide`. An `href` that begins with `//` is a protocol-relative URL, so never "fix" `//example.com/guide` into `/example.com/guide`. Use the `./` prefix for a colon only when it belongs to a real wiki page name, such as `./ADR:0001`. Remove a `javascript:` or placeholder `#` href from a script-controlled element. Do not just strip the scheme off a `javascript:` href, turn `ADR:0001` into `0001`, `mailto:a@b.com` into `./mailto:a@b.com`, or `#` into an invented page path — each one sends readers to the wrong page.

A rejected artifact write comes back as an error result naming the rule that fired (`ruleId`), the reason, the offending element/attribute (`target`) when the rule names one, a `diagnosticCode` for link and resource problems, and a fixed correction message (`message`), so the AI knows what to fix rather than just that the write failed. `target` is an element or attribute name, not a unique position in the body; when the same `a[href]` appears more than once, the AI matches the rule against its own body. The error never contains the rejected value or an HTML fragment.

| `diagnosticCode` | How to fix it |
| --- | --- |
| `PAGE_LINK_QUERY` | Remove the `?...` from the page path |
| `PAGE_LINK_PERCENT_ENCODING` | Use a valid `%HH` after every `%`, or write a literal percent sign as `%25` |
| `PAGE_LINK_RESERVED_ROUTE` | Use an ordinary wiki page path instead of an admin, authentication, API, delivery, page-ID or other reserved route |
| `PAGE_LINK_INVALID` | Remove the `href` of an external URL; write a wiki page as `/guide`, `./guide`, `../guide` or `guide`; remove repeated slashes, control characters, backslashes and invalid escapes |
| `PAGE_LINK_CONTEXT_FORBIDDEN` | On an SVG or MathML `a` and on `img[usemap]` use only a same-document `#id`; put wiki page links on an HTML `a` / `area` |
| `RESOURCE_REFERENCE_FORBIDDEN` | Embed the asset as a `data:` URI in a permitted position; remove an `@import` rule itself, not just its URL |

For a JavaScript syntax error (`MODULE_SPECIFIER_FORBIDDEN`) fix the unclosed parenthesis or brace; for `NORMALIZER_MARKER_INVALID` remove hand-written digest meta markers and any occurrence of the reserved marker name shown in `target` from body text, comments and scripts.

#### When restoring a revision is rejected

`crowi_revert_to_revision` runs the same checks as a save, so restoring a revision that holds a link to a reserved route, which could be saved in the past, can return 400. Stored bodies and rendering are not rewritten. Fix and save it like this:

1. Retrieve that past revision's body with `crowi_get_revision`.
2. Fix the reported HTML issues in the body.
3. Call `crowi_get_page` without `revision_id` to get the current `revision_id` (the `revision_id` returned in step 1 belongs to the past revision and would return 409).
4. Save the corrected body with `crowi_update_page`, passing that current `revision_id`.

## Things to keep in mind

- **The token is your own permissions.** A page you cannot see is invisible over MCP too — and conversely, a write-scoped token can edit anything you can edit.
- **Page bodies are treated as data.** Anyone can write a wiki page, so a body may contain text that reads like an instruction to the AI. Crowi returns page content wrapped in an unguessable delimiter with a note saying it is data and not instructions. Whether a client honours that is ultimately up to the client, so on a wiki with outside contributors, use a read-only token.
- **Calls are rate limited.** A per-user budget stops a runaway agent from hammering the wiki.
