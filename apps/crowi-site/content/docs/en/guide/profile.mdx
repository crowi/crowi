In Crowi, every user has their own "user page" where they can share their
profile and activity with the team. You can also change profile settings
such as your display name and avatar.

## User pages

Every user has a user page at `/user/<username>`. The page is laid
out as follows:

- A **cover** section at the top — a coloured cover band with the
  user's avatar, display name, `@username`, introduction, and a pair
  of stat pills (created pages count, bookmarks count).
- **Three tabs** below the cover:
  - **Pages** — pages the user has **created**. A page shows up here as
    long as this user created it, no matter where it lives (**creator-rooted**).
  - **Bookmarks** — pages the user has bookmarked.
  - **Subpages** — every page that **actually exists under**
    `/user/<username>/`, recursively across all depths, regardless of who
    created it (**path-rooted**). This is a different set from the
    "Pages" tab: a page another user created at, say,
    `/user/<username>/project` shows up here but not under "Pages"; and a
    page this user created outside `/user/<username>/` shows up under
    "Pages" but not here. The tab shows a 10-item preview plus the total
    count, with a "View all" link to a full listing that loads 30 at a
    time. Only pages the viewer is allowed to see (following the same
    grant rules as every other page listing) ever appear.

In addition, by Crowi convention the path `/user/<username>` itself
also works as a **wiki page**. If a page exists at this path, its body
is rendered **below the cover** alongside the tabs. This is useful when
you want to write a longer self-introduction in Markdown.

## Profile settings

Opening "Settings" from the user menu in the header lets you manage
profile-related settings in one place. The settings screen is split into
the following sections.

### Profile information

You can change your display name, email address, and display language.

| Field | Description |
| ----- | ----------- |
| Name | The name shown within the team |
| Email | The destination for notifications. If an administrator has configured a domain restriction for email addresses, an address that does not match the allow list cannot be saved |
| Language (lang) | The display language of the UI (Japanese / English) |

If your account is **linked to an external provider** such as Google, the
**email address cannot be changed**. The field in the settings screen is
disabled and says why (see [Account and security](./account-security)).

The lock depends only on **whether any identity is linked at all**. The
address the provider knows and the address on the Crowi account do not have
to match.

Submitting a different address on such an account **rejects the whole
request: the name and language you changed in the same save are not stored
either.** To change only your name or language, leave the email field as it
is and save (resubmitting your current address saves normally). Accounts
with no linked identity behave exactly as described below.

Name and language take effect the moment you save. **The email address is
the exception — saving alone does not change it.** A message containing a
confirmation link is sent to the new address, and the change is only
applied once you open that link. The confirmation link is valid for
**24 hours**, and once the change has been applied the same link no
longer works (an old link can never revert the address).

A pending link also stops working when:

- **You request a change to a different address.** Only the most recent
  request can be confirmed, so a change you did not start — or one sent to
  an address you mistyped — is called off by simply requesting the right
  one.
- **The account is suspended.** A link issued beforehand cannot be
  confirmed while the account is locked out.

A change you have not confirmed yet is also **cancelled the moment the
account is signed out everywhere** — when you change your own password,
when you complete a password reset, or when an administrator resets your
password. Nothing is lost: request the change again if you still want it.

### Profile picture

You can upload or delete your profile picture (avatar). An uploaded image
is stored in storage and used as your user avatar throughout the app. If
you delete the image, it falls back to an avatar using the initials of
your display name.

Accepted formats are PNG, JPEG, GIF, WebP, SVG, BMP, AVIF, APNG and ICO, up to **5MB per file**. Uploading from a browser will essentially never hit that ceiling — the crop dialog downscales the image before it is sent. The cap matters for routes that skip the crop, such as the CLI, curl, or MCP. When one of those declares no `Content-Type`, the type is **inferred from the filename extension**, so omitting the declaration is not by itself grounds for rejection.
