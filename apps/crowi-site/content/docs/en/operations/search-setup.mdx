Crowi's full-text search is provided through a swappable mechanism called
the **search driver**. The **default driver is `mongo`** — MongoDB-backed
search using `$regex`, implemented by the implicit-default
`@crowi/plugin-search-mongo` plugin. It needs no extra infrastructure, so
a fresh install can search right away on MongoDB alone.

For larger deployments, **Elasticsearch is an opt-in alternative**,
implemented as the `@crowi/plugin-search-elasticsearch` plugin. It scales
better for large corpora and supports Japanese analysis
(`analysis-kuromoji`). This page is for operators and describes how to set
up the Elasticsearch driver and build its index. For the user-facing
search feature, see [Search](../guide/search).

## Architecture overview

- A search driver is loaded as a plugin.
- Which driver is used is specified by `search.driver` in
  `crowi.config.json` (default `mongo`).
- The Elasticsearch driver's connection settings are stored in the Mongo
  Config namespace `plugin:@crowi/plugin-search-elasticsearch:*`.
  Configure them exclusively from the admin UI plugin settings page —
  there is no environment-variable fallback.

## Enabling the Elasticsearch plugin

To switch from the default `mongo` driver to Elasticsearch, declare
`@crowi/plugin-search-elasticsearch` as a dependency of your runner
project, add its name to the `plugins` array in `crowi.config.json`, and
set `search.driver` to `elasticsearch`.

```json
{
  "plugins": [
    "@crowi/plugin-search-elasticsearch"
  ],
  "search": {
    "driver": "elasticsearch"
  }
}
```

Restart the api after editing, and the plugin is loaded and the search
driver is registered. For installing plugins in general, see
[Installing and configuring plugins](./plugins).

## Providing Elasticsearch

You provide the Elasticsearch (or OpenSearch) cluster. To search Japanese
pages, it needs the `analysis-kuromoji` morphological analysis plugin
installed — that is what the `kuromoji` analyzer below uses.

> **Caution**: To use the `sudachi` analyzer
> you must build your own derived image with the `analysis-sudachi` plugin
> and a dictionary bundled in.

In production, prepare either a managed Elasticsearch (Elastic Cloud,
Bonsai, etc.) or a self-operated Elasticsearch cluster.

## Configuring the connection

Connection settings are configured from the plugin settings page in the
admin panel (`/admin/plugins/edit?name=@crowi/plugin-search-elasticsearch`).

| Config key | Description |
| ---------- | ----------- |
| `url` | The Elasticsearch endpoint in `https://[user:pass@]host[:port][/indexName]` format. Because the URL can embed a password, the value is encrypted as sensitive. Booting with this empty leaves the driver **unregistered**; setting a url afterwards cannot reconfigure a driver that was never registered, so **enabling it needs an api restart**. |
| `indexName` | The base index name (default `crowi`). Used when not specified in the URL path. |
| `requestTimeout` | Request timeout in milliseconds (default `5000`). |
| `analyzer` | The mapping flavour. Choose from `default` / `kuromoji` / `sudachi`. |

## Choosing the analyzer

The `analyzer` setting picks the tokenization method for full-text search.

| Analyzer | Cluster requirement |
| -------- | ------------------- |
| `default` | No extra ES plugin needed. |
| `kuromoji` | Requires the `analysis-kuromoji` plugin. |
| `sudachi` | Requires the third-party `analysis-sudachi` plugin and a dictionary. |

For a wiki with mostly Japanese content, `kuromoji` is a safe choice.
If you pick `kuromoji` / `sudachi` on a cluster without the plugin, the
index rebuild described below will fail.

## Building the index

A full rebuild of the search index is done with the `crowi-admin` CLI,
not from the web admin panel. This is by design — long-running work
should not be tied to an admin request.

```bash
crowi-admin rebuild search
```

This command:

1. Loads `.env` and resolves `MONGO_URI` and so on through the same path
   Crowi uses at boot.
2. Resolves the active search driver and asks it to rebuild its index.
3. For the Elasticsearch driver, creates a new timestamped index, bulk
   indexes all pages, and then switches the `<indexName>-current` alias to
   the new index. Old indices are deleted.

`crowi-admin` is an operator-side CLI that connects directly to MongoDB.
Run it from a directory where `@crowi/api` is installed (usually the
runner project).

> **Tip**: Thanks to the alias scheme, searches against the existing index
> continue with no downtime during a rebuild. The alias is switched over
> in one step once the new index is fully built.

If a driver has no persistent index to rebuild, the Search section of the
admin panel shows no rebuild hint.

## Checking the search driver status

The Search section of the admin panel (`/admin/search`) is read-only and
shows the currently active search driver and the list of installed
drivers. Driver switching is done by changing `search.driver` in
`crowi.config.json` and restarting the api. For the admin panel in
general, see [Admin panel](./admin).

## Troubleshooting

- **Driver disabled because `url` is empty**: The connection settings are
  not configured. Set `url` from the plugin settings page in the admin
  panel. While it is empty, searching reports an error and nothing is
  indexed.
- **`rebuild` fails**: You may have picked `kuromoji` / `sudachi` without
  the matching ES plugin installed on the cluster. `crowi-admin rebuild
  search` prints the ES cluster's response body on failure, so check its
  contents.
- **Stale or missing search results**: Incremental indexing on page
  updates is reflected, but taking in older data or mapping changes
  requires a full rebuild with `crowi-admin rebuild search`.
