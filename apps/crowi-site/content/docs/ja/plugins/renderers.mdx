レンダラプラグインは、Crowi のサーバサイド Markdown パイプラインに
パース・変換・描画の振る舞いを追加するプラグインです。設計の詳細は
[RFC-0002](https://github.com/crowi/crowi/blob/main/docs/rfcs/0002-renderer-plugin-architecture.md)
(レンダラプラグインアーキテクチャ) を参照してください。

このページはレンダラプラグインの **概要と一覧** を扱います。利用者として
書ける記法そのものについては [Markdown 記法](../guide/markdown) を、
プラグインの導入手順は [プラグインの導入と設定](./managing) を参照して
ください。

## レンダラパイプラインの考え方

Crowi のレンダラには 3 つの設計上の約束があります。

- **SSR ファースト**: すべてのレンダラプラグインはサーバ側で HTML を
  生成しなければなりません。プラグインコンテンツのクライアントサイド
  レンダリングはレイアウトシフトを起こすため禁止です。
- **編集中は外部 API を叩かない**: 外部データを取得するプラグインは、
  編集中はプレースホルダで領域を確保し、ページ保存時など明示的な
  タイミングでのみ取得します。
- **新しい記法を基本的に増やさない**: プラグインは振る舞いを拡張する
  もので、文法を拡張するものではありません。

レンダラのコアパイプライン (TOC / wikilink / メンション / コードブロック)
は、プラグインより **先に** 登録されます。レンダラプラグインはこの上に
追記する形で動作します。

## キャッシュと失敗時の挙動

embed・コードブロック系プラグインのサーバレンダリング結果はキャッシュ
されます。方式は stale-while-revalidate で、キャッシュ済みの結果を即座に
返しつつバックグラウンドで再レンダリングします。stale ウィンドウを大きく
過ぎたエントリだけ、新しいレンダリングを待ってから返します。

失敗もキャッシュされ、原因ごとのリトライ間隔を持ちます:

- **一時的な上流障害** — ネットワーク・タイムアウトなどの失敗は約 5 分後に
  リトライします。
- **恒久的な失敗** — ポリシーでブロックされた URL や 404 などは約 1 時間後に
  リトライします。
- **認可の失敗** — 1 分後にリトライします。
- **レート制限** — 上流が `Retry-After` を返す場合はそれに従います(上限
  24 時間。ヘッダが無い場合は約 5 分)。

**直前の成功表示の保持** — 再レンダリングが一時的な原因で失敗しても、その
embed が過去に一度でも成功していれば、直前の成功表示が画面に残り続けます
(最後の成功から最大 24 時間。間隔経過後、次にページが表示された
タイミングで再取得を試みます)。404 も
同じ扱いです。上流の一時的な不調や PlantUML サーバの再起動で、表示済みの
図やカードが即座にエラー表示へ置き換わることはありません。

**ポリシー・アクセス権の変化は例外** — SSRF ガードで新たにブロックされた
URL や認可の失敗は、次の再レンダリングで即座に反映されます。古い表示は
保持しません。

**インフラ障害は例外** — 並行数制御(admission control)を使うプラグイン
(現状は Mermaid)で、子プロセスの timeout / crash や並行数超過により
レンダリングが完了しなかった場合は、上記のエラーキャッシュを経由しません。
失敗としてキャッシュされる代わりに「未レンダリング」マークが保存され、
次にそのページが表示されたときに自動で再試行されます。

**失敗時の表示** — プラグインは独自の失敗表示を返せます(リンクカードの
「リンクとして機能するエラーカード」など)。無い場合は汎用のプレース
ホルダが表示されます。

## ファーストパーティのレンダラプラグイン

Crowi のリポジトリには、次の 6 つのレンダラプラグインが同梱されています。

| プラグイン | 役割 | 外部依存 | 状態 |
| ---------- | ---- | -------- | ---- |
| `@crowi/plugin-renderer-emoji` | `:smile:` などのショートコードを Unicode 絵文字へ変換 | なし | 実装済み (Phase 6) |
| `@crowi/plugin-renderer-katex` | `$inline$` / `$$display$$` の LaTeX 数式を KaTeX でサーバ側 HTML 化 | なし | 実装済み (Phase 6) |
| `@crowi/plugin-renderer-plantuml` | ` ```plantuml ` ブロックを PlantUML サーバで描画して SVG/PNG を埋め込む | PlantUML サーバ | 実装済み (Phase 6) |
| `@crowi/plugin-renderer-mermaid` | ` ```mermaid ` ブロックをサーバ内で browserless レンダリングし、サニタイズ済み SVG を埋め込む | なし (サーバ内で完結) | 実装済み (Phase 6.1) |
| `@crowi/plugin-renderer-crowi-legacy` | Crowi v1 由来の記法のクセ (例: `##hoge` の空白なし見出し) を再現 | なし | 実装済み (Phase 6)・既定オフ |
| `@crowi/plugin-renderer-link-card` | `@[card](url)` の URL 先ページを OGP リンクカードとして埋め込み | なし(取得先の外部サイトへ直接 fetch) | 実装済み |

> **Tip**: GitHub の PR / Issue をカード表示する `@crowi/plugin-renderer-github-embed`
> は RFC-0002 で計画されていますが、Phase 7 として進行中であり、まだ出荷
> されていません。

### emoji

`@crowi/plugin-renderer-emoji` は `:smile:` などのショートコードを
`remark-emoji` で Unicode 絵文字に置き換えます。I/O もキャッシュも
ありません。コードブロックとインラインコードは意図的にスキップされ、
未知のショートコード (`:not-emoji:`) はそのまま素通しされます。
スクリーンリーダー向けに `<span role="img" aria-label="smile">` で
ラップする `accessible` モードが既定で有効です。

### KaTeX

`@crowi/plugin-renderer-katex` は `remark-math` で `$inline$` と
`$$display$$` の LaTeX 数式をパースし、`katex.renderToString` で HTML に
変換します。標準的な KaTeX コマンドに対応します。マクロや `\newcommand`
によるカスタマイズは今後の対応予定です。

### PlantUML

`@crowi/plugin-renderer-plantuml` は ` ```plantuml ` のフェンス付き
コードブロックを、運用者が設定した PlantUML サーバへ送信して描画します。
図のソースは deflate + base64 でエンコードされ、サーバから返ってきた
SVG (サニタイズ済み) または PNG が埋め込まれます。

このプラグインは外部サーバを必要とします。Crowi の `docker-compose.yml`
には PlantUML サーバ (`:8080`) が同梱されています。ただしプラグインの
デフォルト `serverUrl` は `http://plantuml:8080`(compose 内部ホスト名)
で、compose ネットワークの外からは解決できません。標準の `pnpm dev`
構成(api はホスト上で実行)では、管理画面で `serverUrl` を
`http://localhost:8080` に設定してください。出力フォーマット
(`svg` / `png`) も同じ管理画面で選択できます。レンダリング結果は
1 時間 TTL でキャッシュされ、ネットワーク障害などの失敗は 5 分間
エラーとしてキャッシュされます。過去に成功した図があれば、PlantUML
サーバが一時的に落ちていても直前の図が表示され続けます(上記
[キャッシュと失敗時の挙動](#キャッシュと失敗時の挙動) を参照)。

### Mermaid

`@crowi/plugin-renderer-mermaid` は ` ```mermaid ` のフェンス付き
コードブロックを、サーバ内で完全に描画します。ブラウザ側で Mermaid の
JS が実行されることは一切なく、ページには最終的なサニタイズ済み SVG を
base64 エンコードした `<img>` としてのみ埋め込まれます。運用者による
設定は不要です — プラグインを有効化するだけで使えます (管理画面に
設定項目はありません)。flowchart / sequence / class / state / ER /
journey / pie / git-graph など、Mermaid が対応する主要な図の種類を
サポートします。

**セキュリティ**: 図はブラウザではなく、`fork()` された隔離子プロセス
内で、外部リソースを一切ロードしない strict 設定の Mermaid によって
描画されます。生成された SVG は独立した DOM ベースのサニタイザ
(`@crowi/plugin-renderer-svg-sanitize`、PlantUML と共有) で `script` /
イベントハンドラ / `javascript:` などを除去したうえで、base64 の
`data:` URL として `<img>` に埋め込まれます。図の設定を上書きする
ディレクティブや外部リソースを参照する構文は、ソース全体を対象に
入力段階で拒否されます。子プロセス自体にも `fetch` / `XMLHttpRequest` /
`node:net` などネットワーク対応 API を削除・遮断する deny-by-default の
境界があり、サニタイズより手前の層でも外部到達を防ぎます。

**テーマ**: 常に 1 種類 (light) のテーマでレンダリングされます。
ダークモードでは、図を囲む領域が中立 (白背景) の面として表示されます。

**制限値**: 図のソースは 20KB、生成される SVG は 60KB までです。1 回の
ページ保存・プレビューあたり同時に処理できる図は最大 50 個です。
図の並行描画は API プロセス(レプリカ)ごとに最大 4 個、うち 1 ユーザー
あたり同一プロセス内で最大 2 個までです(複数レプリカ構成では合計は
その分増えます)。編集中のプレビューは 1 ユーザーあたり
600 リクエスト/60 秒に制限されます。記法エラーのある図は固定の
エラー表示になります。一時的な障害(サーバの過負荷など)でレンダリング
に失敗した場合は、そのページを次に開いたときに自動的に再試行されます。

**既存ページへの適用について**: 既存の ` ```mermaid ` フェンスは、
著者がページを明示的に再保存するまでコードブロックのまま表示され
続けます。プラグインを有効化しただけで過去のページが一括で描画し
直されることはありません。

> **運用者向け**: 上記の子プロセスによるネットワーク遮断に加えて、
> コンテナ/OS レベルの egress 制御 (ネットワーク名前空間の分離など) を
> defense-in-depth として追加で検討することを推奨します。

### crowi-legacy

`@crowi/plugin-renderer-crowi-legacy` は、Crowi v1 由来の標準 Markdown
ではない記法のクセ (例: ハッシュの直後に空白がない `##hoge` を見出しと
みなす) を再現する互換プラグインです。同梱されていますが **既定では
オフ** で、v1 からの移行ユーザーが管理画面で有効化します。

なお、v1 にあった「単一改行を `<br>` にする」挙動は、以前の開発段階では
このプラグインに入っていましたが、現在は Crowi 全体の既定の挙動として
コアパイプラインに移動しています。

### Link card

`@crowi/plugin-renderer-link-card` は、埋め込みタグの登録口
`registry.addEmbedTag(name, renderer)` を実際に使う最初のレンダラプラグイン
です。`@[card](url)` という記法で URL 先ページの OGP メタタグ
(`og:title` / `og:description` / `og:image` / `og:site_name`) を取得し、
タイトル・説明文・ドメイン・(あれば)サムネイル画像を含むリンクカードを
描画します。記法そのものの使い方は [Markdown 記法](../guide/markdown)
の「リンクカード」節を参照してください。

- **画像は直リンク**: `og:image` は取得元サイトへの直リンクとして埋め込まれ、
  プロキシやキャッシュ配信は行いません(v1 の仕様上の決定)。
- **SSRF ガード**: 取得先ホストの DNS 解決結果が private / loopback /
  link-local / unique-local / メタデータ用アドレス(`169.254.169.254` 等)
  である場合は拒否します。IP リテラル指定・DNS 経由・redirect 誘導の
  いずれの経路でも同じ検証を行います(redirect は自動追従せず、最大 3 hop
  まで手動でたどり、各 hop ごとに再検証します)。`http(s)` 以外の scheme
  も即座に拒否します。取得は 5 秒でタイムアウトし、応答は先頭 512KB まで
  しか読みません。DNS rebinding に対する既知の残余リスクについては、
  プラグインの README を参照してください。
- **v1 では allowlist / denylist 設定 UI はありません**。特定ドメインの
  埋め込みを禁止したい場合は、今後の管理設定機能を待つか、フォークして
  独自にガードを追加してください。
- **取得に失敗した場合**(タイムアウト・4xx/5xx・非 HTML コンテンツなど)は、
  URL へのリンクとして機能する最小限のエラーカードに落ちます。過去に
  カードの表示に成功していれば、一時的な失敗では直前のカードが表示され
  続けます(上記 [キャッシュと失敗時の挙動](#キャッシュと失敗時の挙動)
  を参照)。

> **Note**: 上記の `@crowi/plugin-renderer-github-embed`(計画中、未出荷)
> とは別物です。link-card は特定のサービスに限定しない汎用の OGP
> リンクカードで、github-embed が計画している GitHub PR/Issue 専用の
> リッチカード化とは目的も実装も異なります。
