Page history (RFC-0021 Phase 2c-1) gets its first metadata-event writers: changing a page's visibility (`PUT /pages/grant`, and the grant branch of a combined body+grant save) now records a `visibility_changed` event, and a draft's first save that publishes it now records a `draft_published` event, on pages whose history tracking has already started (Phase 2a). Pages that haven't started tracking yet keep behaving exactly as before — no event is written. Both the state change and its event are committed together, so an event is never recorded without the matching state change actually happening, and — except for the one legacy case of a page whose stored grant predates validation and can't supply a truthful before-value — a page's grant/status is never changed on a tracked page without the matching event either; if the event side can't be written (a jammed history outbox), visibility changes fail with the existing 400 response while page content saves keep succeeding as today. Hard-deleting a page and cancelling a draft now also purge that page's history events, so a deleted page's history never outlives it; page content, search indexing, backlinks, notifications, and live-collaboration updates are unaffected. These events are not yet shown anywhere in the UI or any API response — no request/response shape or OpenAPI contract changes.
